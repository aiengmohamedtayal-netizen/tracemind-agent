# Severity classifier

A Random Forest classifier that predicts a severity for every analysed event:
`critical` / `medium` / `normal`. It runs after Isolation Forest inside
`AnalysisOrchestrator.analyze` and is additive: the existing `severity`
display band from Isolation Forest is unchanged, and each event gains
`ml_severity`, `ml_severity_confidence` and `ml_severity_explanation`, while
the analysis result gains a `severity_classification` summary.

## Model

- Algorithm: `RandomForestClassifier` (`n_estimators=200`,
  `class_weight="balanced_subsample"`, `random_state=42`).
- Artifact: `backend/app/models/severity_classifier.joblib` (joblib dict with
  the trained model, feature list, training medians, classes, label-rules
  version and test metrics) plus `severity_classifier.meta.json`.
- If the `.joblib` file is missing (for example on a fresh checkout), the
  backend trains the model once from the bundled training data
  (`backend/app/models/severity_training_data.csv`) and caches it in memory.
- Health check: `/api/health` lists `SeverityClassifier` in `models`.

## Features (15, fixed order)

`anomaly_score`, `isolation_depth`, `is_anomaly`, `latency_ms`,
`error_rate`, `cpu_pct`, `memory_mb`, `payload_bytes`,
`status_error_indicator`, `status_server_error`, `severity_rank`,
`error_term`, `warning_term`, `exception_term`, `component_frequency`.

Telemetry events use their numeric fields directly; generic log events use
their `log_features` (level rank, message terms, frequencies). Missing values
are filled with the training medians stored in the model bundle.

## Labels — rule-derived, not human-verified

There is no human-labelled severity data in this project. Training labels
come from the transparent heuristic rules in
`backend/app/services/severity_labeling.py` (version `v1`):

- R1 critical: anomaly and score >= 0.85.
- R2 critical: HTTP status 5xx and score >= 0.50.
- R3 critical: error rate >= 0.80 and anomaly.
- R4 critical: exception term in the message, anomaly, and score >= 0.60.
- R5 medium: anomaly (no critical rule matched).
- R6 medium: HTTP status 4xx and score >= 0.40.
- R7 medium: error rate >= 0.30 and score >= 0.40.
- R8 normal: otherwise.

## Training data and metrics

Training data is synthetic: 3,000 telemetry events generated by
`backend/scripts/train_severity_classifier.py` in the exact TraceMind schema
(70% routine, 20% degraded, 10% failing), scored by the real Isolation
Forest pipeline (contamination 0.30), then labelled by the rules above.
Rule-label counts: normal 2,100, medium 555, critical 345.

Stratified 80/20 hold-out (seed 42), test size 600:

| class | precision | recall | F1 | support |
|-------|-----------|--------|----|---------|
| critical | 1.0000 | 0.9855 | 0.9927 | 69 |
| medium | 0.9911 | 1.0000 | 0.9955 | 111 |
| normal | 1.0000 | 1.0000 | 1.0000 | 420 |

Accuracy 0.9983, mean confidence 0.9911. Confusion matrix
(rows = true, cols = predicted, order critical/medium/normal):
`[[68, 1, 0], [0, 111, 0], [0, 0, 420]]`.

Read these numbers honestly: they measure how well the forest reproduces
the labelling rules on held-out synthetic data, not performance against
human-verified labels. The one critical miss was predicted as medium.

## Retraining

```bash
PYTHONPATH=backend python backend/scripts/train_severity_classifier.py
PYTHONPATH=backend python backend/scripts/train_severity_classifier.py --data labelled.csv
```

`--data` trains from a real CSV: the telemetry columns plus a
`severity_label` column (`critical` / `medium` / `normal`). When real
operator-confirmed severities exist, retrain from them and bump
`LABEL_RULES_VERSION` in `severity_labeling.py`.

## Response shape

Per event (additive, old fields unchanged):

```json
{
  "ml_severity": "critical",
  "ml_severity_confidence": 0.97,
  "ml_severity_explanation": "Needs attention now: this event is highly unusual (anomaly score 0.92) with a 503 status and an error rate of 0.95."
}
```

Run-level summary (additive, next to `isolation_forest`):

```json
{
  "severity_classification": {
    "model": "SeverityClassifier",
    "model_version": "severity-classifier v1",
    "algorithm": "RandomForest",
    "classes": ["critical", "medium", "normal"],
    "label_rules_version": "v1",
    "labels_note": "Training labels are rule-derived heuristics, not human-verified.",
    "total_events": 120,
    "counts": {"critical": 4, "medium": 18, "normal": 98},
    "mean_confidence": 0.97
  }
}
```

If the model cannot be loaded or trained, analysis still completes and the
summary reports `"status": "skipped"` with a reason instead of failing the
run. Investigation actions remain read-only; the classifier only triages.
